# Archive a local readable snapshot of saved pages

A saved link should stay readable after the source dies. Until now the ladder preserved the generated understanding (title, summary, permitted excerpt) and locally archived imagery, but not the page's readable content itself. This decision adds a Readable Snapshot: a reader-mode text copy of the page — the harness extracts it with its own browser at save time (typically Markdown) and attaches it as a file via `stumble add --snapshot` or `stumble pod content snapshot`. The CLI copies the file under the node's media directory and records a `readable_snapshot` Submission Asset pointing at it; re-attaching replaces the archived copy in place.

Snapshots inherit the strictly-local rule that already governs every asset with bytes: nothing under the media directory federates, full stop. A snapshot is additionally a copy of someone else's page rather than the node's own work, so it also never appears in `media_references`, a Pod Package, or any other shared surface — what travels between nodes remains exactly the summary and reference-first URLs. The permitted-excerpt boundary keeps governing everything shared; the snapshot is the user's private on-device archive of a page they already read, like a browser cache that outlives the tab.

A snapshot records where its text came from: `page-text` (extracted from the live page) or `user-provided` (text the user supplied, e.g. for pages the harness cannot reach). An AI-generated snapshot source is rejected — a snapshot is an archive of what the page said, never a depiction; generated retellings stay in the summary, where provenance is honest by construction.
